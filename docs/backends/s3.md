# AWS S3 Backend

Syncs the bundle to an S3 bucket using the AWS CLI.

## Prerequisites

```bash
# macOS
brew install awscli

# Linux
pip install awscli
```

## Setup

1. **Configure AWS credentials:**
   ```bash
   aws configure
   ```
   Enter your AWS Access Key ID, Secret Access Key, and default region.

2. **Create an S3 bucket:**
   ```bash
   aws s3 mb s3://your-kirocrew-sync-bucket
   ```

3. **Enable versioning (recommended):**
   ```bash
   aws s3api put-bucket-versioning \
     --bucket your-kirocrew-sync-bucket \
     --versioning-configuration Status=Enabled
   ```

4. **Point the backend at your bucket** in `backends/s3.sh`:
   ```bash
   S3_BUCKET="your-kirocrew-sync-bucket"
   AWS_PROFILE="default"  # or your profile name
   ```

5. **Select the backend:**
   ```bash
   export SYNC_BACKEND=s3
   ./kirocrew-sync.sh push
   ```

   Or set it permanently in `config.sh`:
   ```bash
   export SYNC_BACKEND="s3"
   ```

## Settings

| Variable | Default | Meaning |
| --- | --- | --- |
| `S3_BUCKET` | `your-bucket-name` | Bucket the bundle is written to |
| `S3_PREFIX` | `kirocrew-sync` | Key prefix (folder) inside the bucket |
| `AWS_PROFILE` | `default` | AWS CLI profile used for credentials |

Each is read from the environment first, so you can override any of them in
`config.sh` instead of editing `backends/s3.sh`.

## Usage

```bash
./kirocrew-sync.sh push     # aws s3 sync bundle -> s3://$S3_BUCKET/$S3_PREFIX/
./kirocrew-sync.sh pull     # aws s3 sync s3://$S3_BUCKET/$S3_PREFIX/ -> bundle
./kirocrew-sync.sh status   # bucket reachability and last remote sync time
```

Push runs with `--delete`, so the remote prefix mirrors the bundle exactly.
`.lock` and `.tmp` files are excluded in both directions.

## Troubleshooting

```bash
# Check AWS credentials
aws sts get-caller-identity

# List bucket contents
aws s3 ls s3://your-bucket/kirocrew-sync/
```

If `push` or `pull` fails with "Cannot access S3 bucket", the profile in
`AWS_PROFILE` either lacks credentials or has no access to `S3_BUCKET` — the
backend probes with `aws s3 ls` before every operation.

## Security

- AWS credentials live in `~/.aws/credentials` and are never part of this repo.
- Data in transit is HTTPS.
- The bundle contains your full chat history and knowledge base — keep the
  bucket private, and prefer a dedicated IAM user scoped to this one bucket.
